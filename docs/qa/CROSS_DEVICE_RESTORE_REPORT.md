## 2. Key Challenges & Architectural Solutions

### 2.1 The Absolute Path Trap in Android Cross-Device Restore
- **The Problem:** In Android, every installed app has a sandbox path that includes the package name and user ID (e.g., `/data/user/0/com.example.simple_aac_app/app_flutter/`). On secondary user profiles or work profiles, this becomes `/data/user/10/...`. When switching devices or cloning apps, hardcoded absolute paths break immediately because the file path does not exist on the target device.
- **The Solution:** 
  1. **Portable Archive Packaging:** When `BackupService.buildBackupZip()` generates a backup, all physical media files are mapped to clean relative paths inside the archive (`files/images_<id>_<timestamp>.jpg` and `files/voices_<id>_<timestamp>.m4a`).
  2. **Active Device Re-anchoring:** Upon restore on the target device, `BackupService.restoreFromBackupDir()` extracts each file into the target device's active `CardStorageService.mediaDirectory()` (`app_flutter/aac_media/{images,voices}/`), dynamically rewriting `card.imagePath` and `card.voicePath` to the target device's actual absolute path.
  3. **Foreign Absolute Path Recovery:** If a backup archive generated by a third party or older app version contains hardcoded foreign paths in `cards.json` (e.g., `imagePath: "/data/user/0/foreign.package/app_flutter/photo.jpg"`), the restored service strips directory prefixes, checks the backup archive's `files/` folder for `photo.jpg`, and re-anchors it onto the destination device instead of dropping it.

### 2.2 Android 10–15 Scoped Storage Compliance
- Under Android 10+ (API 29+) Scoped Storage and Android 13+ (API 33+) granular media permissions:
  - App documents (`getApplicationDocumentsDirectory()`) do **not** require runtime `READ_EXTERNAL_STORAGE` or `READ_MEDIA_IMAGES` permissions.
  - Data saved here survives across reboots and is completely isolated from other applications and OEM cleaning utilities.
  - User backups exported to `Downloads/` utilize Android's `MediaStore.Downloads` API, requiring zero broad storage permissions while remaining accessible to the user via Google Drive, WhatsApp, or file managers.

### 2.3 Media Deduplication and Collision Avoidance
- If the destination device already contains a file with the identical name and identical content (same file length and SHA-256 hash), the restore engine reuses the existing file directly without duplicating storage.
- If a filename matches an existing file with **different** content, the engine increments a suffix (`photo_1.jpg`, `photo_2.jpg`), preventing accidental overwriting.
